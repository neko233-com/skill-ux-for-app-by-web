# 判别：游戏 UI 还是应用 UI？

目标：给 spec 的 `kind` 字段定值。**不确定时问用户一句**，不要瞎猜后返工。

## 决策树

```
用户是否在描述游戏内界面 / 游戏产品？
├─ 明确游戏词（见下）          → kind = "game"
├─ 明确应用词（见下）          → kind = "app"
├─ 两者都有（如游戏内「设置页」）→ 跟随产品外壳：
│     界面从游戏内打开、有游戏货币/HUD/角色  → "game"
│     界面是官网 / 社区 / 工具 / 后台        → "app"
└─ 完全模糊                    → 向用户确认（给 2 选 1 + 理由）
```

## 易混场景

| 场景 | 判定 |
|---|---|
| 游戏官网 / 预约页 / 社区 | app（用 app 风格，可选 ios-clean / glass / brutalist） |
| 游戏内设置 / 邮件 / 好友 | game（外壳仍是游戏，用轻量 game 风格如 flat / apple-game） |
| 带游戏化元素的教育/打卡 App | app（除非有战斗/养成数值） |
| 电竞 / 直播间 UI | app，但可把 style 指到 neon-arcade 借气质 |
| 桌面工具 + 华丽动效 | app，选 brutalist 或 glass |

## kind 定下之后

- `kind=game` → 风格包从 `styles/game/` 选；默认 chrome 是 HUD + dock
- `kind=app`  → 风格包从 `styles/app/` 选；默认 chrome 是 header + tabbar
- 产出的 HTML 外壳形态（手机框、底部导航）也随 kind 变化

判别结果要在交付时**用一句话告诉用户**：
「已识别为 **游戏原型**，选用风格 **二次元**」——让用户有机会纠偏。
