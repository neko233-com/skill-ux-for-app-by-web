# 工作流 05 · 嵌入飞书文档

产出的 HTML 是**单文件、零外链、file:// 可用**的，满足三种飞书用法。

## 路线 A · 附件（最稳，推荐策划同学）

1. 把 `.html` 作为附件上传到飞书文档 / 云盘 / 群文件
2. 同事下载后双击，用浏览器打开即可完整交互
3. 适合：内网、需要完整动效、评审前分发

> 交付话术：「下载后用 Chrome/Edge 打开，所有交互可点。」

## 路线 B · 嵌入网页（在线可看，需可访问 URL）

飞书文档：`/` 唤起快捷插入 → **嵌入网页**（或「更多 → 网页」）→ 粘贴 URL。

要求：
- URL 必须是 **https**（或公司内网可解析的 http）
- 页面不能禁止 iframe（构建产物默认允许）
- 建议挂到：公司静态托管 / GitHub Pages / 内网 Nginx / 飞书云文档同域的静态服务

示例（GitHub Pages）：
```bash
# 若仓库开了 Pages，把 out.html 推到 docs/ 或 gh-pages 分支后即可获得
# https://<user>.github.io/<repo>/out.html
```

嵌入尺寸建议：宽 375–420（手机原型）或 1024–1200（桌面后台原型）。

## 路线 C · 粘贴截图 + 链接（评审批注场景）

1. 对关键屏截图（可用 `pg.screenshot`）
2. 截图插入飞书文档做批注
3. 文档里留 HTML 文件链接，标注「可交互原件」

> 注意：直接从浏览器复制粘贴 HTML **会丢失交互**，只保留近似富文本。
> 所以不要把「粘贴」当成交付方式。

## 构建时已保证的飞书兼容性

| 点 | 产物行为 |
|---|---|
| 无外链 | 校验器强制 |
| 编码 | 显式 UTF-8 |
| 移动端 | viewport meta + 响应式手机框 |
| iframe 沙箱 | 不用 window.open / 不用 XHR-fetch |
| 字体 | 系统字体栈，不加载 webfont |
| 图形 | 纯 CSS + emoji，不依赖图片 CDN |
| 体积 | 校验默认 < 500KB，通常 60–120KB |

## 常见问题

**Q：嵌入后是白屏？**  
多半 URL 不通或对方网络访问不到。改走路线 A 附件。

**Q：嵌入后能看不能点？**  
检查是不是粘贴成了富文本；必须用「嵌入网页」或附件。

**Q：手机上打开布局乱？**  
产物在 ≤640px 宽时自动全屏铺满；若 custom 块写死宽度需要改 spec。

**Q：想内网在线预览又没有公网？**  
任意内网静态服务器即可：`python -m http.server 8000 --directory .`，
然后嵌 `http://内网IP:8000/out.html`。
