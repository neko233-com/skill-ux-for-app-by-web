# 工作流 02 · 从历史风格参考图选型

输入：用户给的 1~N 张历史 UI 截图 / 风格参考图。输出：`spec.style`（+ 可选 token 覆盖）。

## 原则

**能对齐内置包就对齐内置包**（视觉稳定、可维护）；气质完全对不上才写 custom。

## 步骤

1. **用视觉能力逐张读图**，记录风格指纹：
   - 主色 / 辅色 / 底色（尽量给 hex 估计）
   - 圆角尺度（直角 / 小圆 / 大圆胶囊）
   - 阴影语言（无 / 柔 / 硬位移 / 描边）
   - 字重对比（轻 / 中 / 极粗大写）
   - 密度（留白大 / 信息密）
   - 装饰（描边、渐变、光效、纹理、像素、水墨…）
2. **对照 catalog 做匹配打分**（0-3 分/维度）：

   | 维度 | 权重 |
   |---|---|
   | 色彩气质 | 3 |
   | 阴影/描边语言 | 3 |
   | 圆角 | 2 |
   | 字体气质 | 2 |
   | 整体密度 | 1 |

3. **取最高分的包**作为 `style`；若最高分 < 7/11，进入 custom 流程
4. **微调**：用 `tokens.overrides` 覆盖 1-3 个关键色即可，
   不要把整份 palette 抄进 overrides（难维护）
   ```json
   "tokens": { "overrides": { "palette.primary": "#实际主色", "palette.bg": "#实际底色" } }
   ```
5. **交付时说明**：
   > 参考图最接近 **「supercell 欧美卡通」**，已将主色覆盖为图中的 #FFB020。
   > 如需完全还原参考图的特殊纹理，可改为 custom 风格包。

## 写 custom 风格包

1. 复制 `styles/_template.tokens.json` → `styles/custom/<slug>.tokens.json`
2. 按指纹填全 token；`id` 必须等于文件名
3. 需要特殊纹理时在 `scripts/chrome-recipes.css` 加：
   ```css
   [data-style="<slug>"] .ux-card { /* ... */ }
   ```
4. 重新 build；custom 包要提交进仓库（这样下次同项目可复用）

## 多图冲突

用户给了风格不一致的多图：
- 问清楚「以哪张为主」
- 或：主图定 kind/style，辅图只取单一维度（如只取辅图的主色）
